Robot + Object MCGDF World Model

구조 내장형(gray-box) 물리 World Model — 동작 흐름 · 접촉(Contact) 모델 · 학습 목적
경로: scripts/world_model/Physics/Robot_and_Object/MCGDF/

1. 이 모델이 풀려는 문제 (Task의 목적)

Franka 9-DOF 로봇 팔이 물체(cube)를 들어올리는(Lift) 시뮬레이션에서, 현재 상태와 앞으로 가할 토크가 주어졌을 때 로봇과 물체의 미래 궤적을 다중 스텝으로 예측하는 World Model을 학습하는 것이 목표입니다.

핵심 설계 철학은 "신경망으로 전부 예측"이 아니라 아는 물리는 방정식으로 고정하고, 모르는 부분만 신경망에 맡기는 구조 내장형(structured / gray-box) 접근입니다. 그래서:

  • 아는 것 (방정식 고정): 강체 운동방정식, 관성행렬의 양정부호성, 코리올리 항, Franka 기구학(Jacobian), 물체의 Newton-Euler 동역학, 쿼터니언 적분.
  • 모르는 것 (신경망 추정): 관성행렬 H(q), 중력 g(q), 잔차 토크 rθ, 그리고 로봇 그리퍼가 물체에 가하는 접촉 렌치 F_c.
왜 이렇게 하나? 비교 문서 delan_vs_physx_verification.tex에서 학습된 DeLaN 동역학과 PhysX 시뮬레이터를 대조해 발견한 9가지 불일치(mismatch)를 하나씩 고친 결과가 이 MCGDF 설계입니다. 구조를 박아두면 데이터가 적어도 물리적으로 타당한(관성행렬이 항상 양정부호, 작용-반작용 보존) 예측을 합니다.

2. 상태(State) 표현 — 31차원

구성차원내용
로봇 q9관절 위치 (7 arm + 2 finger)
로봇 q̇9관절 속도
물체 pos3위치 (env-local 좌표, env_origin 차감)
물체 quat4방향 (wxyz 쿼터니언)
물체 lin_vel3선속도 (world frame)
물체 ang_vel3각속도 (world frame)
합계 state_dim = 31로봇 18 + 물체 13

+ 부수 입력: 토크 τ(9), 관절 damping/friction, 물체 context ξ(질량 1 + 관성 9 + 재질 3 = 13).

3. 한 스텝(one step)이 진행되는 방식

코드: RobotObjectMCGDFStep.forward() — state → next_state 를 매 스텝 반복(open-loop rollout).

① 상태 분해 — 31차원 state를 q, q̇, 물체 pos/quat/lin_vel/ang_vel 로 split.
↓
② DeLaN 구조항 계산 — 신경망이 하삼각 L을 내고 H = L·Lᵀ + εI (항상 양정부호 관성행렬). 코리올리 c는 H의 미분에서 해석적으로 유도. 중력 g(q)는 작은 MLP.
↓
③ 접촉 렌치 예측 (Contact)  ← 4절에서 상세
ContactWrenchHead가 6차원 접촉 렌치 F_c = (힘 3, 토크 3) 예측.
↓
④ 로봇이 받는 반작용 토크 — 해석적 Franka Jacobian으로 τ_contact = −J_c(q)ᵀ·F_c (뉴턴 제3법칙).
↓
⑤ 잔차 토크 — rθ(q, q̇, τ)가 implicit-PD 액추에이터/수치오차 보정.
↓
⑥ 로봇 가속도 풀기 — 운동방정식을 실제로 선형풀이: H·q̈ = τ + rθ − c − g − f·tanh(q̇/ε) + τ_contact → q̈ = solve(H, rhs).
↓
⑦ 물체 가속도 (Newton-Euler) — 같은 F_c로 물체 선/각가속도 계산.
↓
⑧ 적분 (dt) — 로봇 q,q̇는 semi-implicit Euler. 물체 위치/속도는 Euler, 방향(quat)은 exp-map 적분으로 다음 31차원 state 생성.

4. 접촉(Contact) 관련 부분 — 모델의 핵심

로봇과 물체를 잇는 유일한 통로가 하나의 접촉 렌치 F_c ∈ R⁶입니다. 로봇→물체로 작용하는 힘/토크를 신경망이 예측하고, 물체와 로봇이 같은 F_c를 공유하므로 작용-반작용이 자동으로 보존됩니다.

4.1 접촉 렌치 예측 — ContactWrenchHead

F_c = ContactWrenchHead( state, τ, ξ ) ∈ R⁶ F_c[:3] = 물체에 가하는 힘 (world frame) F_c[3:] = 물체 질량중심 둘레 토크 (world frame)

입력은 전체 state + 토크 + 물체 context(질량·관성·재질). MLP(또는 context latent z로 FiLM 변조) 구조.

4.2 로봇 쪽 반작용 — 해석적 Franka Jacobian

Jacobian은 학습하지 않고 Franka의 실제 링크 파라미터로 미분 가능하게 계산 (FrankaForwardKinematics.jacobian). 7개 arm 관절은 z축 회전, finger 2개는 그리퍼 tip을 움직이지 않으므로 Jacobian의 8·9열은 0.

τ_contact = − J_c(q)ᵀ · F_c (뉴턴 제3법칙: 그리퍼가 받는 반작용)

4.3 물체 쪽 — Newton-Euler 강체 동역학

선형: mₒ · v̇ₒ = mₒ · g + F_c[:3] 회전: I_w · ω̇ₒ + ωₒ × (I_w · ωₒ) = F_c[3:] 관성: I_w(rₒ) = R(rₒ) · I_b · R(rₒ)ᵀ (몸체관성을 월드프레임으로 회전)

각가속도는 I_w ω̇ = F_c[3:] − ω×(I_wω)를 선형풀이해서 구함 (자이로스코픽 항 포함).

4.4 쿼터니언 적분 — exp-map (mismatch #4 수정)

qₘ₊₁ = qₘ ⊗ exp( ½ ωₒ dt ) exp([0, v]) = [ cos|v|, (sin|v|/|v|) v ] (소각도는 테일러 전개로 안정화)

단순 Euler 적분 대비 회전 정확도가 높음. (옆 폴더 No_object_Euler/가 이걸 Euler로 바꾼 비교군.)

4.5 학습 시 접촉 신호 정리 — Contact onset & residual baseline

데이터셋(dataset.py)이 물체가 처음 움직이는 시점을 접촉 개시(contact onset)로 감지하고, 접촉 전 구간의 평균 잔차(pre-contact baseline)를 per-step 잔차 타깃에서 빼줍니다. 이렇게 하면 rθ는 비접촉 동역학만, F_c는 순수 접촉 기여만 담당하도록 역할이 깔끔히 분리됩니다 (검증 문서 mismatch #2, Approach A).

아직 단순화된 가정: 접촉점을 그리퍼 중점 하나로 봅니다. 두 손가락 각각의 Jacobian으로 나누거나 마찰원뿔(friction cone) 제약을 거는 것은 향후 개선 항목(README의 Open items).

5. Context 인코더 (옵션) — 미지 물리 파라미터 적응

물체 질량·마찰 등을 모를 때를 위해, 과거 (state, torque) 히스토리에서 per-episode latent z를 뽑는 변분 인코더(ContextEncoder, VAE식 KL + InfoNCE 대조학습)를 둡니다. z는 FiLM으로 각 헤드(H, c, g, residual, contact)를 변조합니다. 기본값은 꺼져 있어(use_context_encoder=False) 끄면 pre-FiLM 동작과 정확히 일치 — 하위호환을 깨지 않는 opt-in 설계.
